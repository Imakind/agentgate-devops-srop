# Как устроен AgentGate

Данные проходят простой путь:

```text
JSON trace + policy
        ↓
load_json → validate_trace / validate_policy
        ↓
evaluate: tools → domains → approvals → tokens → calls
        ↓
единый детерминированный report
        ↓
Flask UI/API | CLI | JSON/JUnit export
```

`core.py` не импортирует Flask и не выполняет сетевые запросы. Его можно тестировать и использовать отдельно. `app.py` отвечает только за HTTP, ограничения тела запроса, безопасную выдачу статических файлов и скачивание результатов. `cli.py` читает ограниченный объём данных, вызывает тот же evaluator и переводит результат в exit code.

Изменение политики не переписывает trace. Пересчёт выполняется заново для всех шагов; результат зависит только от trace и policy. Каждый шаг может иметь несколько нарушений. В отчёте число failed steps и количество отдельных violations показаны раздельно.

Браузерный интерфейс не исполняет строки журнала, не открывает его URL и не вставляет предоставленные пользователем тексты как HTML. Content Security Policy запрещает сторонние скрипты, inline scripts, фрейминг и объекты. Тексты ошибок API проходят тот же безопасный JSON-вывод. Эти меры не заменяют аутентификацию или полноценный аудит безопасности.

В CI файл wheel — граница между Build и Test. Второй job скачивает и устанавливает сборку первого job. Благодаря `src/`-структуре и `--import-mode=importlib` pytest импортирует установленный пакет. Тесты HTTP проверяют и наличие упакованных HTML/CSS/JS, чтобы успешная сборка без интерфейса не прошла незаметно.
