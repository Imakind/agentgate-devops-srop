# AgentGate

[![AgentGate CI](https://github.com/Imakind/agentgate-devops-srop/actions/workflows/ci.yml/badge.svg)](https://github.com/Imakind/agentgate-devops-srop/actions/workflows/ci.yml)

**Проверь поведение агента до того, как доверишь ему действие.**

AgentGate — компактная учебная информационная система для проверки JSON-трасс AI-агентов. Русскоязычная панель показывает нарушения по шагам, позволяет менять политику и повторно проверять trace. CLI возвращает ненулевой exit code при нарушениях, поэтому ту же проверку можно использовать в CI.

Это **детерминированный анализ предоставленного журнала**, а не генеративная модель или защитный шлюз, перехватывающий реальные действия. API-ключи, платные сервисы и внешние запросы не нужны. Все встроенные трассы — явно помеченные учебные сценарии.

## Возможности

- 5 групп проверок: разрешённые инструменты, точные домены, заявленные подтверждения, суммарные токены и число вызовов.
- 3 сценария: корректное исследование, нарушение границ, зацикленный поиск.
- Импорт JSON, просмотр каждого шага, изменение политики и повторная оценка.
- Экспорт воспроизводимого JSON и JUnit XML, тёмная и светлая темы.
- Строгая схема входных данных: до 100 шагов и 512 KiB; неизвестные поля и повторяющиеся ключи отклоняются.
- Настоящая сборка Python wheel + sdist и отдельный этап тестирования именно собранного wheel.

## Стек

Python 3.12, Flask, vanilla JavaScript/CSS, pytest, setuptools, GitHub Actions. Runtime- и dev-зависимости зафиксированы по версиям в requirements-файлах. Actions закреплены по commit SHA; workflow имеет только `contents: read` и не использует пользовательские секреты.

## Быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m build --no-isolation
python -m pip install --no-deps dist/agentgate-1.0.0-py3-none-any.whl
agentgate serve
```

Откройте http://127.0.0.1:5050. Команда запускает локальный Flask-сервер без debug-режима. `--port` принимает 1–65535; 0 отклоняется. Для повторной сборки после изменения кода установите wheel с `--force-reinstall --no-deps`.

## CLI

```bash
agentgate check src/agentgate/fixtures/01-research.json
agentgate check src/agentgate/fixtures/02-boundary.json --format junit --output violations.xml
python -m agentgate check trace.json --policy policy.json
```

Exit codes: **0** — trace соответствует политике; **1** — найдены нарушения; **2** — ошибочный ввод/файл/аргументы. Второй пример намеренно завершается с кодом 1.

## Сборка и тестирование

```bash
python -m build --no-isolation
python -m pip install --force-reinstall --no-deps dist/agentgate-1.0.0-py3-none-any.whl
python -m pip check
python -m pytest -v --junitxml=reports/pytest.xml
```

Используется структура `src/`, тесты не дописывают исходники в `sys.path`: импортируется установленный пакет. В набор входят проверки правил и границ бюджета, обходов доменного allowlist, привязки approval, некорректного JSON, API, содержимого wheel и exit codes CLI. Число фактически выполненных тестов видно в pytest и артефакте `agentgate-test-results`.

## CI: Install / Build → Test

Workflow: [`.github/workflows/ci.yml`](.github/workflows/ci.yml).

1. **Install / Build**: checkout → Python 3.12 → установка зафиксированных зависимостей → `python -m build --no-isolation` → загрузка wheel и sdist как артефактов.
2. **Test built wheel**: запускается только после успешного Build (`needs: build`); получает именно его артефакт, устанавливает wheel и выполняет pytest с JUnit-отчётом.
3. Ошибка команды приводит к неуспешному job. Ошибка Build не допускает Test. Ошибка теста делает pipeline неуспешным. JUnit загружается и при падении тестов, если файл успел сформироваться.

Триггеры: **push**, **pull_request** и ручной **workflow_dispatch**. Отчёты и сборки хранятся 14 дней. Workflow реализует CI и упаковку; автоматического развёртывания в production (CD) здесь нет. Наличие YAML или успешные локальные тесты не означают успешного удалённого запуска: его подтверждает конкретный run в GitHub Actions.

## Структура

```text
.github/workflows/ci.yml     # два зависимых CI job
src/agentgate/core.py        # чистая валидация и пять групп правил

src/agentgate/cli.py         # терминальный интерфейс и exit codes
src/agentgate/fixtures/      # три учебных трассы
src/agentgate/static/        # панель без frontend-зависимостей

pyproject.toml              # метаданные и настоящая сборка wheel
requirements*.txt           # зафиксированные зависимости
```

## Схема и ограничения

Формат данных, пример политики и точные правила: [docs/trace-format.md](docs/trace-format.md).

- Политика применяется к предоставленным данным. Можно подделать trace или approval: подписи, личности, полнота журнала и фактическое выполнение действий не проверяются. PASS не является гарантией безопасности.
- Запись approval должна ссылаться на конкретный шаг и инструмент с решением `approved`. Это проверка согласованности записи, а не подтверждение, полученное от реального пользователя.
- Домены сравниваются точно после lowercase/IDNA/удаления одной завершающей точки. Поддомены не разрешаются автоматически. Необратимые Unicode-преобразования IDNA (например, `faß.de` → `fass.de`) отклоняются; для таких имён используйте точное ASCII/Punycode-представление. URL никогда не открываются сервером. Проверка не анализирует DNS, содержимое страниц, редиректы и безопасность текста.
- Домен проверяется только у явно указанного URL; для `web.open` URL обязателен. Другие сетевые инструменты без поля URL не дают достаточных данных для проверки назначения. Один шаг считается одним вызовом. Токены берутся из trace, а не измеряются токенизатором.
- Базы данных, регистрации, аутентификации и долговременного хранения нет. Редактор политики действует в текущей вкладке. JSON отправляется только локальному серверу; приложение не добавляет телеметрию. Не загружайте реальные секреты.
- Сервер по умолчанию слушает только `127.0.0.1`. Не публикуйте этот учебный dev-сервер в интернете.

## Учебное назначение

Проект подготовлен для СРОП по DevOps, **вариант 50 (выбран для работы, не заявляется как назначенный преподавателем)**:

> Создать собственное небольшое приложение для информационной системы. Настроить полный базовый pipeline Install/Build → Test и продемонстрировать его успешное выполнение.

Разработка выполнена с помощью AI. Перед защитой необходимо самостоятельно запустить проект, изучить код и уметь объяснить решения и результаты. Не следует утверждать, что каждая строка написана без помощи.

Почему тема актуальна: практики [evaluation AI-агентов (Anthropic)](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) и [устойчивости к prompt injection (OpenAI)](https://openai.com/index/designing-agents-to-resist-prompt-injection/) подчёркивают значение проверяемого поведения. AgentGate демонстрирует лишь узкую детерминированную часть этой области и не заявляет защиту от всех атак.
